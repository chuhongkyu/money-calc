## 1. 제품 개요

| 항목       | 내용                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------- |
| 한 줄 소개 | 연봉을 넣으면 **지금 시점 기준 월 실수령액**을 바로 보여주고, 조건을 더 넣으면 더 정확해지는 계산기 |
| 목표       | 복잡한 기능보다 **깔끔한 UX와 정확한 입력**으로 검색 유입과 앱 설치를 이끌고, 광고로 수익을 냄      |
| 1차 타깃   | 이직이나 연봉협상을 앞둔 직장인, 사회초년생                                                         |
| 배포 대상  | ① 모바일 웹 (SEO 유입) ② iOS 앱 ③ Android 앱. 코드는 하나로 같이 씀                                 |
| 수익 모델  | 광고 (앱은 AdMob, 웹은 카카오 애드핏 또는 AdSense) + **광고 제거 인앱결제**                         |

### 핵심 원칙

1. **정확성이 최우선이다.** 숫자가 틀리면 앱의 존재 이유가 사라진다. 모든 계산은 테스트로 검증한다.
2. **연도별 규칙은 코드가 아니라 데이터다.** 매년 바뀌는 값은 `rules/` 데이터 파일만 수정하면 반영돼야 한다.
3. **입력 경험이 곧 제품이다.** 숫자 입력, 콤마, 단위 표시, 키보드 처리를 공들여 만든다.
4. **광고가 계산 경험을 방해하지 않는다.** 광고는 결과를 본 뒤에 나오고, 빈도를 제한하며, 끌 수 있다.

## 4. 기능 명세 (MVP)

### 4.1 기준 시점(asOf) 하나로 규칙을 고른다

연도 탭을 고르게 하지 않는다. **기준일 하나**(기본값: 오늘)로 아래 두 가지를 자동으로 조합한다.

| 항목                                  | 바뀌는 단위                                      | 데이터                                   | 선택 규칙                                      |
| ------------------------------------- | ------------------------------------------------ | ---------------------------------------- | ---------------------------------------------- |
| 4대보험 요율·국민연금 상하한·최저임금 | 달력 연도 (국민연금 상하한은 7월)                | `rules/YYYY.ts`                          | 기준일의 연도. 상하한은 기준일이 속한 `period` |
| 근로소득 간이세액표                   | 국세청 고시 적용 시작일 (예: 2024.3.1, 2026.3.1) | `rules/incomeTaxTable/<YYYY-MM-DD>.json` | `effectiveFrom ≤ 기준일 ≤ effectiveTo`         |

- 메인 화면은 기준일을 묻지 않고 **오늘 기준**으로 계산한다. 결과에 "2026년 9월 기준 · 국민연금 4.75%" 뱃지를 보여주고, 누르면 `RulesInfoActivity`로 이동한다.
- 기준일을 고르는 UI는 두지 않는다 (제품 결정 2026-09-22). 항상 오늘 기준. 과거 기준으로 보는 기능은 "옛날 기준으로 보고 싶어요?" 정도로 필요해지면 붙인다. 도메인은 `asOf` 를 받으므로 UI 만 추가하면 된다.
- 이전 연도 규칙이 있으면 결과 화면에 "○○년 같은 시점 대비 월 −○○원" 한 줄을 보여준다 (1년 전 같은 날짜 기준으로 동시에 계산). 2027년 규칙이 추가되면 자동으로 켜진다.
- 새 연도 추가는 `rules/2027.ts`, 새 간이세액표는 `incomeTaxTable/2027-03-01.json`을 만들고 레지스트리에 등록하면 끝나야 한다. **UI 코드는 수정할 필요가 없어야 한다.**

#### 규칙 데이터 스키마 (예시)

```ts
// rules/types.ts
export interface YearRules {
  year: number;
  label: string; // "2026년"
  description: string; // "4대보험 2026년 요율 (국민연금 상·하한은 7월에 변경)"
  verified: boolean; // 사람이 공식 자료와 대조했는지 여부
  sources: string[]; // 근거 URL
  nationalPension: {
    totalRate: number; // 0.095
    employeeRate: number; // 0.0475
    periods: Array<{
      from: string; // "2026-01-01"
      to: string; // "2026-06-30"
      monthlyIncomeMin: number; // 기준소득월액 하한
      monthlyIncomeMax: number; // 기준소득월액 상한
    }>;
  };
  healthInsurance: { totalRate: number; employeeRate: number };
  longTermCare: {
    rateOfIncome: number; // 소득 대비 요율 (예: 0.009448)
    rateOfHealthPremium: number; // 건보료 대비 비율 (예: 0.1314)
    calcMethod: "ofHealthPremium" | "ofIncome"; // 실제 고지 방식에 맞게 선택
  };
  employmentInsurance: { employeeRate: number }; // 0.009
  incomeTax: {
    tableId: string; // 연 단위 검증(골든 테스트)용 기본 표. 실제 조회는 기준일(asOf)로 고른다
    localTaxRate: number; // 지방소득세 = 소득세의 10%
    withholdingOptions: [0.8, 1.0, 1.2];
  };
  defaults: {
    nonTaxableMealMonthly: number; // 식대 비과세 기본값 200,000
  };
}
```

### 4.2 입력 명세: 가장 공들일 부분

#### `MoneyInput` 상세 요구사항 (반드시 모두 구현)

- `inputMode="numeric"`, `pattern="[0-9]*"`로 모바일에서 **숫자 키패드**가 뜨게 한다.
- 입력하면서 **실시간으로 천 단위 콤마**를 넣는다. 콤마가 들어가도 **커서 위치가 튀지 않아야 한다.** (가장 흔한 버그이므로 테스트를 작성할 것)
- 입력 아래에 **한글 금액**을 표시한다. 예: `45,000,000` → "4,500만 원"
- **빠른 입력 칩**: `+100만` `+500만` `+1,000만` `초기화`
- 붙여넣기할 때 숫자 이외의 문자는 제거한다. (예: "4,500만원" 붙여넣기 → 45,000,000)
- 앞자리 0은 자동으로 없애고, 음수나 소수는 막는다.
- 최대값: 연봉 10억, 월급 1억. 넘으면 입력을 막고 helper text로 안내한다.
- 지우기(×) 버튼을 둔다.
- 입력 중에는 **디바운스 없이 즉시 계산**해서 하단 요약(월 실수령액)을 실시간으로 갱신한다. 계산은 순수 함수라 가볍다.
- 키보드가 올라와도 하단 CTA 버튼이 가려지지 않게 한다. (iOS 웹뷰 `visualViewport` 처리, Capacitor Keyboard 설정)
- 접근성: label을 연결하고, 스크린리더가 "4,500만 원"처럼 읽게 한다.

#### 유효성 검증

- 월 급여에서 비과세액을 뺀 값이 0 이하면 결과를 막고 안내한다.
- 최저임금보다 낮은 입력도 계산은 하되, 안내 문구를 보여준다. (최저임금 값도 `rules`에 둔다.)

### 4.3 계산 로직

```
월 급여     = 연봉 ÷ (퇴직금 포함 ? 13 : 12)
과세 급여   = 월 급여 − 비과세액
국민연금    = clamp(과세 급여, 하한, 상한) × 근로자 요율        (원 단위 절사, 공단 기준 확인)
건강보험    = 과세 급여 × 근로자 요율                            (원 단위 절사)
장기요양    = 규칙의 calcMethod에 따라 계산                      (원 단위 절사)
고용보험    = 과세 급여 × 0.9%                                   (원 단위 절사)
소득세      = 간이세액표(과세 급여, 부양가족 수, 자녀 수) × 원천징수 비율
지방소득세  = 소득세 × 10%                                        (원 단위 절사)
실수령액    = 월 급여 − (위 공제액 합계)
```

- **소득세는 공식 근로소득 간이세액표를 데이터(JSON)로 옮겨서 조회**하는 방식을 기본으로 한다. 월 1,000만 원을 넘는 구간은 표 하단에 있는 산식을 코드로 구현한다.
- 자녀 세액공제 반영 방식(자녀 수별 차감액)은 해당 연도 간이세액표의 주석을 그대로 따른다.
- 단수 처리(절사 또는 반올림, 10원 단위 등)는 기관마다 다르므로 각 항목의 공식 기준을 확인해서 `rules`에 명시한다.
- 결과 타입에는 항목별 금액, 합계, 연간 환산, 적용한 규칙 버전을 넣는다.

#### 테스트 (필수)

- `domain/salary/__tests__/golden.test.ts`에 **연도별 20개 이상의 골든 케이스**를 둔다. 연봉 2,400만 / 3,000만 / 4,000만 / 5,000만 / 7,000만 / 1억 / 1.5억에 부양가족과 자녀 조합을 섞는다.
- 기대값은 **국세청 간이세액표와 4대보험 모의계산 결과를 사람이 확인한 값**으로 채운다. Claude는 기대값을 추측으로 채우지 말고 `TODO(verify)`로 남긴다.
- 커버리지: `domain/` 90% 이상.

### 4.5 광고 시스템

#### 원칙

- **입력 중에는 광고를 절대 띄우지 않는다.** (입력 화면에는 배너도 두지 않는 것을 기본으로 한다.)
- 광고 위치:
  1. **결과 화면 하단 배너**: 상시 노출
  2. **전면 광고**: "결과 보기"를 눌러 결과 화면으로 넘어갈 때만 띄우고, **빈도 제한**을 건다
  3. (선택) **리워드 광고**: "연도 비교 상세" 같은 부가 기능을 열 때
- **첫 실행 뒤 첫 N회(기본 2회)는 전면 광고를 띄우지 않는다.** 전면 광고 사이에는 최소 간격(기본 3분)과 세션당 최대 횟수(기본 3회)를 둔다. 모든 값은 `ads/config.ts` 한곳에서 관리한다.
- 광고 로드에 실패해도 사용자 흐름은 **절대 막히지 않는다.** 타임아웃은 1.5초이고, 실패하면 광고 없이 그대로 진행한다.

#### 추상화 계층

```ts
// ads/types.ts
export interface AdProvider {
  init(): Promise<void>;
  showBanner(slot: "result_bottom"): Promise<void>;
  hideBanner(): Promise<void>;
  showInterstitial(placement: "to_result"): Promise<"shown" | "skipped" | "failed">;
  showRewarded?(placement: string): Promise<"rewarded" | "dismissed" | "failed">;
}
```

구현체:

| 구현체          | 사용 환경                                                             |
| --------------- | --------------------------------------------------------------------- |
| `AdMobProvider` | iOS/Android 앱 (Capacitor)                                            |
| `WebAdProvider` | 모바일 웹 (애드핏/AdSense 배너만. 웹에서는 전면 광고를 쓰지 않음)     |
| `NoopProvider`  | 광고 제거를 구매한 사용자, 개발 모드, 스크린샷 모드, 광고 비활성 빌드 |

`ads/index.ts`의 `getAdProvider()`가 **환경과 사용자 상태로 구현체를 고른다.** UI 컴포넌트는 구현체를 직접 import하지 않는다.

### 4.6 광고 제외(광고 제거) 처리

"광고를 빼는 경로"를 빠짐없이 한곳(`ads/policy.ts`의 `shouldShowAds()`)에서 판단한다.

| 제외 조건                                 | 방법                                                                 |
| ----------------------------------------- | -------------------------------------------------------------------- |
| **광고 제거 구매자**                      | RevenueCat entitlement `no_ads`. 구매 복원 버튼 필수 (iOS 심사 요건) |
| **개발/미리보기**                         | `import.meta.env.DEV` 또는 `VITE_ADS_ENABLED=false`                  |
| **스토어 스크린샷 촬영**                  | `?screenshot=1` 또는 빌드 플래그                                     |
| **웹 특정 경로 제외**                     | 개인정보처리방침, 이용약관, 계산 기준 안내 페이지 등은 광고 없음     |
| **추적 동의 거부 (iOS ATT) 또는 EU 동의** | 광고는 띄우되 **비개인화 광고**로 전환 (UMP SDK)                     |
| **원격 킬스위치**                         | (향후) Remote Config로 전체 또는 특정 지면 광고를 즉시 끔            |

- 구매 즉시 배너가 사라져야 한다. (구독 상태를 반응형으로 반영)
- 설정 화면: `광고 제거 (₩○○○, 1회 결제)` / `구매 복원`
- 테스트 광고 ID와 실제 광고 ID를 환경변수로 분리한다. **개발 중 실제 광고 ID로 노출하거나 클릭하는 일이 없도록** 한다.
